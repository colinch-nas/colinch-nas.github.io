Home Assistant 2026.9.1로 업데이트했다면 NAS 백업이 실제로 저장되고 복구되는지 바로 확인하는 게 좋다. 9월 5일 패치에서 `receive backup streaming`과 백업 파일 수신 과정의 잠금 문제가 수정됐다. 기능이 추가된 건 아니지만, NAS를 백업 대상으로 쓰는 사용자에겐 실패를 놓치지 않게 된 패치다. ([공식 2026.9 릴리스 노트](https://www.home-assistant.io/blog/2026/09/02/release-20269/))

이 글은 Synology DSM 7.4, Home Assistant 2026.9.1의 OS 설치, 공유기 내부망 `192.168.0.0/24` 환경에서 확인한 설정이다. Home Assistant Container나 Core 설치는 메뉴가 다르므로 그대로 따라 하면 안 된다.

## NAS에 백업 폴더 만들기

DSM에서 `제어판 → 공유 폴더`로 들어가 `homeassistant-backup`을 만든다. 이 폴더에는 NAS 계정 `ha_backup`만 읽기·쓰기 권한을 주고, 관리자 계정이나 전체 사용자 권한은 주지 않았다. 스냅샷과 휴지통은 켜도 되지만, 랜섬웨어가 NAS 계정까지 탈취하면 함께 지워질 수 있으므로 이것만으로 백업이 끝났다고 보면 안 된다.

| 항목 | 권장값 | 이유 |
|---|---|---|
| 프로토콜 | SMB/CIFS | Synology에서 만들기 쉽고 HA OS가 지원 |
| SMB 버전 | 2.1 이상 | Home Assistant 네트워크 저장소 요구사항 |
| 공유 폴더 | `homeassistant-backup` | 미디어·문서와 분리 |
| 계정 | `ha_backup` 전용 | 관리자 계정 노출 방지 |

그림에서 봐야 할 부분은 Home Assistant와 NAS가 같은 내부망에 있고, 백업 전용 공유 폴더가 다른 데이터와 분리돼 있다는 점이다.

## Home Assistant 2026.9.1에서 연결

`설정 → 시스템 → 저장소 → 네트워크 저장소 추가`를 선택한다. 아래처럼 입력하고 연결한다.

```text
이름: synology_backup
용도: 백업
서버: 192.168.0.20
프로토콜: Samba/CIFS
공유: homeassistant-backup
사용자 이름: ha_backup
비밀번호: NAS에서 만든 전용 비밀번호
```

SMB 공유 입력란에 `/volume1/homeassistant-backup` 전체 경로를 넣으면 실패했다. 이 화면의 `공유`에는 공유 폴더 이름만 넣어야 한다. CIFS는 SMB 2.1 이상만 지원하므로 Synology의 `제어판 → 파일 서비스 → SMB → 고급 설정`에서 최소 SMB 프로토콜도 확인한다. ([Home Assistant 네트워크 저장소 공식 문서](https://www.home-assistant.io/common-tasks/os/#network-storage))

연결이 끝나면 `설정 → 시스템 → 백업 → 설정 및 기록`에서 점 3개 메뉴를 열고 기본 작업 위치를 `synology_backup`으로 바꾼다. 자동 백업 위치에서는 NAS와 로컬을 둘 다 켰다. NAS 연결이 끊긴 순간에도 로컬 백업 하나는 남아야 하기 때문이다.

## 2026.9.1 패치 후 검증 순서

수동 백업을 하나 만든 뒤 NAS 공유 폴더에 `.tar` 파일이 생기는지 확인한다. 파일 크기가 0KB가 아니고, Home Assistant 백업 화면에서 해당 백업의 내용 목록이 열려야 한다. 여기서 끝내지 말고 테스트용 장비나 별도 VM에서 복구 화면까지 진입해본다. 복구를 실행하지 않아도 암호화 키와 파일 손상 여부를 확인할 수 있다.

자동 백업은 `설정 → 시스템 → 백업 → 자동 백업 구성`에서 하루 1회로 두고 보존 개수는 7개 정도로 시작했다. Recorder 데이터가 커지면 백업도 불필요하게 커진다. `설정 → 시스템 → 복구 → 시스템 정보`에서 데이터베이스 크기를 확인하고, 장기 기록이 필요하지 않다면 보존 기간을 줄인다. 백업은 압축 파일이므로 NAS 용량이 넉넉해도 복구 시간은 파일 크기에 비례한다. ([Home Assistant 백업 안내](https://www.home-assistant.io/common-tasks/general/#backups))

## 운영 전 체크리스트

- [ ] `synology_backup` 상태가 연결됨으로 표시되는가
- [ ] 수동 백업 파일이 NAS에 생성되는가
- [ ] 백업 화면에서 파일 목록과 암호화 키가 확인되는가
- [ ] 로컬 백업 위치도 하나 남겨뒀는가
- [ ] NAS 계정에 공유 폴더 외 권한을 주지 않았는가
- [ ] 한 달에 한 번 복구 화면까지 테스트할 일정이 있는가

Home Assistant 2026.9.1 업데이트의 핵심은 새 백업 메뉴가 아니라 백업 전송 과정의 안정화다. NAS를 연결해놓고 성공 여부를 확인하지 않았다면, 오늘 수동 백업 1회와 복구 화면 진입 1회만 해도 가장 위험한 빈틈을 찾을 수 있다.
