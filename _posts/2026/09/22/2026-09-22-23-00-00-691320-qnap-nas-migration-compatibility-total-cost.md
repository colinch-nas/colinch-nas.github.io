QNAP NAS를 새 제품으로 교체할 때 디스크를 빼서 꽂는 방법이 가장 싸 보이지만, **같은 OS 계열이고 공식 호환이 확인된 직접 시스템 마이그레이션**일 때만 그렇다. QTS에서 QuTS hero로 바꾸거나 호환 목록에 없는 모델이면 새 풀과 데이터 복사 비용까지 넣어야 한다. 별도 백업이 없다면 디스크를 바로 옮기는 구매는 피하는 편이 안전하다.

## 구매 전에 확인할 기준

QNAP 공식 마이그레이션 목록은 소스·대상 모델과 베이 수를 조합해 직접 이동 가능 여부를 보여준다. 두 장비는 같은 OS 계열이어야 하고, 대상 NAS는 원본 디스크를 수용해야 한다. 양쪽 OS를 최신 상태로 맞추는 것도 권장된다.

| 확인 항목 | 통과 조건 | 통과하지 못하면 |
|---|---|---|
| 운영체제 | QTS→QTS, QuTS hero→QuTS hero | 새 풀 생성 후 데이터 복사 |
| 베이 수·디스크 | 원본 디스크 수용, 호환 HDD | 호환 HDD 교체 또는 백업 복원 |
| RAID 디스크 순서 | 원래 슬롯 순서 유지 | 인식 실패·복구 작업 위험 |
| SSD 캐시 | 이동 전에 캐시 비활성화 | 캐시 제거 후 재점검 |
| 레거시 볼륨 | 새 볼륨으로 이전 계획 | 전체 백업 후 새 볼륨에 복원 |

QTS와 QuTS hero 사이는 파일 시스템이 달라 지원되지 않는다. JBOD·확장 장치 조합도 따로 확인해야 한다. 포트 트렁킹, 가상 스위치, Thunderbolt, USB QuickAccess 설정은 달라질 수 있으므로 “데이터가 보인다”를 “운영이 복구됐다”로 보면 안 된다.

## 직접 이동과 새로 복원하는 비용

아래 숫자는 특정 판매 가격이 아니라 비교용 가상 사례다. 4베이 QNAP과 4개의 12TB HDD를 쓰다가 6베이 모델로 바꾼다고 가정했다.

| 방식 | 추가 장비 | 작업 부담 | 복구 실패 시 비용 |
|---|---:|---|---|
| 직접 시스템 마이그레이션 | 새 NAS | 낮음 | 원본 디스크 손상 시 높음 |
| 새 풀+LAN 복사 | 새 NAS+임시 백업 디스크 | 중간 | 원본을 보존하면 낮음 |
| 새 풀+외장 백업 복원 | 새 NAS+백업 HDD | 높음 | 백업 검증이 됐으면 가장 예측 가능 |

가상 계산으로 새 NAS 60만 원, 임시 12TB 외장 HDD 25만 원으로 잡으면 직접 이동은 약 60만 원, 새 풀 복사는 약 85만 원부터다. 외장 HDD가 이미 있거나 기존 NAS를 백업 서버로 남기면 추가 구매는 줄어든다. 반대로 디스크 이동은 25만 원을 아끼지만, 판단을 틀리면 복구 업체 비용과 다운타임이 커질 수 있다.

## 실행 전 체크리스트

- [ ] QNAP 공식 호환성 도구에서 소스·대상 모델 조합을 확인한다.
- [ ] 두 NAS의 QTS/QuTS hero 계열과 펌웨어 버전을 기록한다.
- [ ] 디스크를 슬롯 번호로 표시하고 현재 RAID·볼륨·암호화 키를 보관한다.
- [ ] SSD 캐시와 Qtier를 해제하고, 확장 장치 호환성을 확인한다.
- [ ] 설정 백업만 믿지 말고 파일 1개와 공유 권한 1개를 복원해 본다.
- [ ] 직접 이동이 불가하면 원본 NAS를 보존한 채 새 풀을 만들고 데이터를 복사한다.

QNAP도 직접 마이그레이션이 지원되지 않으면 새 NAS를 초기화한 뒤 백업·복원 또는 네트워크 전송을 사용하라고 안내한다. 호환 목록과 원본 백업이 모두 있을 때만 디스크 이동을 선택하고, 하나라도 없으면 새 풀과 복사 비용을 포함하는 편이 낫다.

공식 기준은 [QNAP NAS 시스템 마이그레이션 호환성](https://www.qnap.com/ko-kr/nas-migration?os=qts&source=ts-230)과 [QNAP의 도메인 컨트롤러 마이그레이션 FAQ](https://www.qnap.com/ko-kr/how-to/faq/article/will-nas-domain-controller-environment-is-preserved-after-nas-migration)에서 확인할 수 있다. 두 문서 모두 호환 여부 확인 전 디스크 초기화나 새 스토리지 풀 생성을 하지 말라고 안내한다.
