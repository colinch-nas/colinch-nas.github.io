![Home Assistant 2026.9 Modbus 설정](https://www.home-assistant.io/images/blog/2026-09/social.png)
이 이미지는 Home Assistant 2026.9에서 Modbus 장치를 로컬 네트워크로 연결하는 흐름을 보여주는 대표 이미지다.

Home Assistant Core 2026.9부터 Modbus 장치를 연결하는 방식이 조금 현실적으로 바뀌었다. Synology NAS에서 Docker로 Home Assistant를 돌리고 있다면, 지원되는 인버터는 레지스터 주소를 YAML에 일일이 적지 않고 UI에서 장치를 추가할 수 있다. 2026년 9월 2일 공식 릴리스 기준으로 Fronius, Sofar Inverter Modbus, Flexit이 이 구조를 사용한다.

## 이번 설정의 환경

| 항목 | 기준값 |
|---|---|
| NAS | Synology DS923+ |
| NAS OS | DSM 7.2.2 |
| Home Assistant | Core 2026.9, Docker 컨테이너 |
| 연결 방식 | Modbus TCP, 기본 포트 502 |
| 예시 장치 | Fronius 또는 지원되는 Sofar 인버터 |

핵심은 Home Assistant 컨테이너가 인버터와 같은 내부망에 있어야 한다는 점이다. 공유기에서 포트 502를 인터넷으로 열 필요는 없다. 오히려 이 포트를 외부 공개하면 전력 장치의 관리면을 불필요하게 노출하게 된다.

## 인버터에서 Modbus TCP 켜기

Fronius Gen24·Tauro·Verto는 장치 웹 화면의 `Communication > Modbus`에서 Modbus TCP 서버를 켠다. Datamanager가 있는 모델은 `Settings > Modbus`에서 `Data output via Modbus`를 TCP로 바꾼다. Fronius Gen24는 펌웨어에 따라 `Solar API`도 별도로 활성화해야 한다.

Sofar는 모델에 따라 Modbus TCP 메뉴 이름이 다르지만, 네트워크 포트가 없으면 RS485-이더넷 브리지가 필요하다. 인버터의 IP는 DHCP 예약으로 고정했다. DHCP 주소가 바뀌면 NAS의 Home Assistant가 갑자기 다른 장치를 조회하게 되기 때문이다.

## Home Assistant에서 장치 추가

Home Assistant 화면에서 `설정 > 기기 및 서비스 > 통합 추가`로 들어가 `Fronius` 또는 `Sofar`를 검색한다. 자동 검색이 안 되면 수동으로 추가하고 다음 값을 넣는다.

| 입력값 | 예시 | 확인할 점 |
|---|---|---|
| Host | `192.168.10.55` | 인버터의 내부 IP 또는 로컬 DNS |
| Modbus TCP port | `502` | 장치에서 변경했다면 실제 포트 |
| Unit ID | `1` | Sofar 설정에 따라 달라질 수 있음 |

Fronius는 기존 Solar API와 Modbus TCP를 함께 사용할 수 있다. Modbus를 추가하면 MPP Tracker(태양광 스트링별 최대전력점 추적기)의 전압·전류·전력·누적 에너지 센서가 생길 수 있다. Sofar는 시리얼 번호를 읽어 모델과 레지스터 맵을 자동 판별한다. 응답은 오지만 모델을 인식하지 못하면 지원 목록에 없는 장치일 가능성이 크다.

## NAS Docker에서 막힐 때 확인할 순서

처음에는 컨테이너 네트워크를 `bridge`로 두고도 당연히 연결될 줄 알았는데, NAS 방화벽 규칙이 컨테이너 대역을 막고 있어 실패했다. 컨테이너에서 장치까지 실제로 닿는지 확인하려면 Home Assistant 컨테이너가 있는 환경에서 목적지 포트만 검사한다. 아래 명령의 컨테이너 이름과 IP를 환경에 맞게 바꾼다.

```bash
docker exec -it homeassistant sh -c 'nc -vz -w 3 192.168.10.55 502'
```

`succeeded`가 나오면 Home Assistant 설정 문제일 가능성이 높다. 실패하면 NAS 방화벽의 출발지 대역, 인버터의 Modbus 활성화 여부, VLAN 간 ACL(네트워크 간 통신 허용 규칙)을 확인한다. Home Assistant를 IoT VLAN에 넣었다면 인버터가 있는 VLAN으로 TCP 502만 허용하는 규칙을 두는 편이 안전하다.

Modbus 장치는 여러 클라이언트가 동시에 붙을 때 불안정해질 수 있다. 2026.9의 새 연결 구조는 같은 인버터를 조회하는 통합들이 연결을 공유하도록 설계됐지만, 별도의 모니터링 프로그램이나 Node-RED가 이미 세션을 점유하고 있다면 장치 한계에 걸릴 수 있다. 기존 YAML Modbus 설정과 새 통합을 같은 장치에 중복 적용하지 않는 것도 중요하다.

## 설정 후 확인할 것

- 장치 페이지에서 인버터 상태와 생산 전력이 갱신되는지 확인한다.
- MPP Tracker 센서는 기본 비활성일 수 있으므로 필요한 센서만 활성화한다.
- 밤처럼 인버터가 절전 상태인 시간에는 Modbus 센서가 늦게 나타날 수 있다.
- 전력량을 장기 기록할 경우 단위가 `W`인지 `kWh`인지 확인하고 Energy 대시보드에 등록한다.
- 외부 접속은 포트포워딩 대신 기존 Tailscale 또는 Home Assistant Cloud를 사용한다.

이번 업데이트의 포인트는 YAML 설정이 완전히 사라졌다는 뜻이 아니다. 지원 장치는 UI 흐름이 쉬워졌고, 아직 지원되지 않는 전력계는 기존 Modbus 통합과 장치 설명서의 레지스터 맵이 필요하다. Synology NAS에서는 `고정 IP → 내부 TCP 502만 허용 → UI 통합 추가 → 센서 단위 확인` 순서로 점검하면 삽질 범위를 크게 줄일 수 있다.
