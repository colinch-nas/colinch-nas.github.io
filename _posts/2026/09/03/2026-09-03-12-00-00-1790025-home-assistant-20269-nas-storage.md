*이 그림에서 볼 것은 Home Assistant 서버와 별도 NAS에 백업을 나눠 두는 구성이다.*

Home Assistant 2026.9에서는 연결한 네트워크 저장소의 사용량을 Storage 화면에서 바로 확인할 수 있다. Synology NAS를 백업 위치로 붙여 두면 백업 파일이 쌓이다가 공유 폴더가 가득 차는 상황을 늦게 발견하는 문제를 줄일 수 있다. 2026년 9월 2일 공식 릴리스 기준으로 사용량이 85%를 넘으면 주황색, 95%를 넘으면 빨간색으로 표시된다.

## 테스트 환경

이번에 확인한 구성은 Synology DSM 7.2.2와 Home Assistant OS 2026.9다. Home Assistant는 별도 미니 PC에 설치했고, NAS와 같은 가정용 LAN에 두었다. Home Assistant를 NAS Container Manager에서 운영하는 경우에도 화면 이름은 거의 같지만, SMB 마운트를 컨테이너에 직접 넘기는 구성은 별도 권한 설정이 필요하므로 이 글의 UI 연결 방식부터 적용하는 편이 안전하다.

| 항목 | 설정값 |
|---|---|
| NAS 공유 폴더 | `ha-backup` |
| NAS 전용 계정 | `ha_backup` |
| 공유 프로토콜 | SMB |
| 외부 공개 | 하지 않음 |
| 백업 보존 | 전체 백업 7개부터 시작 |

## Synology에 전용 공유 폴더 만들기

DSM에서 **제어판 → 공유 폴더 → 생성**을 열고 `ha-backup`을 만든다. 이 폴더에는 Home Assistant 전용 계정만 읽기·쓰기 권한을 준다. 관리자 계정이나 NAS 전체 공유 권한을 사용하면 Home Assistant가 침해됐을 때 다른 파일까지 노출될 범위가 커진다.

계정 생성 후 **제어판 → 파일 서비스 → SMB**에서 SMB 서비스를 켠다. SMB 최소 버전은 DSM의 기본 권장값을 유지하고, 공유 폴더의 휴지통은 백업 파일이 이중으로 쌓일 수 있으므로 이 폴더에서는 꺼 두었다. NAS 방화벽을 쓰고 있다면 Home Assistant의 고정 IP만 SMB 접근 대상으로 허용한다.

## Home Assistant 2026.9에서 NAS 연결

이제 Home Assistant의 **설정 → 시스템 → 저장소**로 이동한다. 네트워크 저장소 영역에서 **네트워크 저장소 추가**를 선택하고 아래처럼 입력한다.

```text
이름: synology_backup
사용 목적: 백업
프로토콜: SMB
서버: 192.168.0.20
공유: ha-backup
사용자 이름: ha_backup
비밀번호: NAS 전용 계정 비밀번호
```

서버 주소에는 `smb://`를 붙이지 않고 NAS의 내부 IP만 입력했다. 저장 후 연결 상태가 정상인지 확인하고, Storage 화면에서 `synology_backup` 행에 용량 막대와 “사용 중 / 전체 용량”이 보이는지 확인한다. 연결이 끊긴 공유 폴더는 용량 막대 대신 경고 상태로 표시되므로, 숫자가 안 보인다고 용량이 0이라고 판단하면 안 된다.

## 백업 예약과 복구 확인

**설정 → 시스템 → 백업**에서 전체 백업을 한 번 수동으로 만든다. 저장 위치에 `synology_backup`을 선택하고, 자동 백업은 하루 1회·보존 7개로 시작했다. 애드온과 미디어까지 포함하면 파일 크기가 빠르게 커질 수 있어 실제 사용량을 하루 뒤 다시 확인하는 것이 좋다.

| 확인 항목 | 통과 기준 |
|---|---|
| 수동 전체 백업 | 성공 상태와 생성 시각 확인 |
| NAS 파일 | `ha-backup`에 새 파일 생성 |
| 용량 표시 | 사용량과 전체 용량이 표시됨 |
| 복구 | 테스트 장비에서 백업 목록을 읽음 |

백업이 성공했다는 알림만 믿지 말고 NAS의 공유 폴더에서 파일 생성 시각을 확인했다. 더 중요한 것은 복구다. 운영 인스턴스에서 바로 복원하지 말고 여분 디스크나 테스트 VM에 백업을 복원해 대시보드, 자동화, 애드온 설정이 살아나는지 확인한다. NAS 스냅샷은 실수 복구에는 유용하지만, NAS 자체 고장이나 랜섬웨어를 대신 막아 주는 외부 백업은 아니다.

## 막혔던 지점과 보안 체크

처음에는 NAS 호스트명을 입력했는데 이름 해석이 되지 않아 연결이 실패했다. 내부 DNS가 따로 없는 집이라면 `192.168.0.20`처럼 고정 DHCP 주소를 쓰는 편이 덜 흔들린다. SMB 포트 445를 공유기에서 포트포워딩하는 방식은 사용하지 않는다. 외부 접속은 이미 구성한 VPN이나 인증된 역방향 프록시를 사용하고, SMB는 LAN 안에만 남겨야 한다.

Home Assistant 2026.9의 NAS 용량 표시는 백업을 대신하는 기능이 아니라 운영 상태를 일찍 알려주는 기능이다. `전용 SMB 계정 → 자동 백업 → NAS 용량 확인 → 별도 복구 테스트` 순서를 한 번 묶어 두면, 백업 파일이 조용히 쌓이거나 연결이 끊긴 상태를 훨씬 빨리 알아챌 수 있다.
