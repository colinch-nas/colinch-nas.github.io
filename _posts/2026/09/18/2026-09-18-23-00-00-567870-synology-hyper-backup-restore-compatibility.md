그림에서 볼 부분은 NAS 본체보다 백업 대상과 복원 장비의 조건을 따로 확인해야 한다는 점이다.

Synology NAS를 교체할 예정이라면 **Hyper Backup 작업이 성공했다는 이유만으로 새 NAS에서 전체 복원이 된다고 보면 안 된다.** DSM 7.3·7.4 공식 사양 기준으로 전체 시스템 복원 대상은 원본과 같거나 더 높은 모델이어야 하고, 드라이브 수·사용 가능한 공간·HDD/SSD 구성과 슬롯 순서도 맞아야 한다. 사진과 문서만 복원할 사람은 이 조건이 훨씬 느슨하다. 따라서 새 장비를 사기 전에는 “전체 시스템 복원”인지 “파일·패키지 복원”인지부터 구분해야 한다.

## 복원 방식에 따라 필요한 NAS가 달라진다

| 백업 유형 | 교체 NAS 조건 | 구매 판단 |
|---|---|---|
| 전체 시스템 | 원본과 같거나 상위 모델, 같은 드라이브 수 이상, 같은 용량 이상 | 베이 수와 디스크 배치를 우선 확정 |
| 공유 폴더·파일 | Hyper Backup과 백업 저장소에 접근 가능하면 모델 제약이 작음 | 2베이로도 가능하지만 앱 설정은 별도 확인 |
| 패키지 포함 백업 | 새 DSM에서 해당 패키지 지원 필요 | Docker·Photos 등 패키지별 지원 여부 확인 |
| `.hbk` 파일 탐색 | Hyper Backup Explorer가 실행되는 PC 필요 | NAS를 바로 사지 않고 파일부터 꺼낼 수 있음 |

Synology 공식 문서에서 전체 시스템 복원은 원본 NAS와 같은 수 이상의 드라이브, 필요한 저장 공간, 동일한 드라이브 유형과 삽입 슬롯을 요구한다. 예를 들어 원본이 4베이에서 HDD 3개와 SSD 1개를 사용했다면, 새 NAS에 SSD 1개와 HDD 3개를 아무 순서로 꽂아도 된다고 가정하면 안 된다. 이 조건은 단순 파일 복원과 가장 크게 갈리는 지점이다. [Hyper Backup 기술 사양](https://www.synology.com/en-sg/dsm/7.4/software_spec/hyper_backup)

## 교체 전에 확인할 숫자 5개

가상 사례로 2베이 NAS가 8TB HDD 2개를 사용하고, 실제 사용량이 5.2TB라고 하자. 전체 시스템 복원을 목표로 한다면 다음처럼 확인한다.

| 확인 항목 | 원본 예시 | 교체 장비에서 볼 값 |
|---|---:|---:|
| 모델 등급 | DS220+ | DS220+ 이상인지 |
| 드라이브 수 | 2개 | 2개 이상인지 |
| 복원에 필요한 공간 | 5.2TB 이상 | 백업 데이터와 시스템 영역을 수용하는지 |
| 드라이브 유형 | HDD 2개 | HDD 2개인지 |
| 슬롯 순서 | 1번·2번에 HDD | 동일한 순서로 장착 가능한지 |

여기서 “8TB 두 개를 샀으니 충분하다”는 계산은 위험하다. RAID 유형, 파일 시스템, 예약 공간, 패키지 데이터가 달라지면 표시 용량과 복원 가능 공간이 달라진다. 새 NAS의 베이 수가 모자라거나 SSD와 HDD 구성이 달라지면 전체 시스템 복원 대신 파일·폴더를 선택 복원하는 계획으로 바뀐다.

## 실제 구매 전 복원 체크리스트

백업 디스크나 원격 NAS를 바로 새 장비에 연결하기 전에 아래 기록을 남긴다.

- [ ] Hyper Backup 작업의 백업 유형이 전체 시스템인지 확인했다.
- [ ] 원본 모델과 DSM 버전, 설치된 패키지 목록을 저장했다.
- [ ] 원본의 디스크 수·유형·슬롯 순서를 사진으로 남겼다.
- [ ] 새 모델이 전체 시스템 복원 지원 모델인지 제품 사양에서 확인했다.
- [ ] 암호화 백업의 암호와 키를 NAS와 다른 장소에 보관했다.
- [ ] 테스트용 파일 3개와 Docker 설정 파일 1개를 별도 복원할 계획을 세웠다.
- [ ] 복원 실패 시 Hyper Backup Explorer로 파일을 꺼낼 PC를 준비했다.

Hyper Backup은 다중 버전·암호화·무결성 검사를 제공하지만, 백업 성공 알림이 서비스 전체의 복구 테스트를 대신하지는 않는다. 특히 암호화된 볼륨과 공유 폴더는 잠금 해제 상태에서만 백업할 수 있고, `.hbk` 다중 버전 백업은 Hyper Backup 계열 도구에서 읽는다. [Hyper Backup Explorer 지원 범위](https://www.synology.com/en-sg/dsm/7.4/software_spec/hyper_backup)

## 언제 구매를 보류할까

다음 중 하나라도 확인되지 않으면 새 NAS 구매보다 복원 설계부터 끝내는 편이 낫다.

1. 새 모델의 전체 시스템 복원 지원 여부가 제품 문서에 없다.
2. 원본이 4베이인데 예산 때문에 2베이 모델로 내려가야 한다.
3. 원본은 HDD와 SSD를 섞었지만 새 장비에는 같은 순서로 장착할 수 없다.
4. 백업 암호, 패키지 버전, 컨테이너 데이터 경로를 모른다.
5. 복원 후 서비스를 확인할 별도 PC나 테스트 폴더가 없다.

이 경우의 총비용은 NAS 가격만이 아니다. `새 NAS + 복원용 디스크 부족분 + 백업을 임시 보관할 외장 디스크 + 복원에 걸리는 작업 시간`으로 계산해야 한다. 파일만 복원하면 기존 NAS를 잠시 유지하면서 새 NAS를 준비할 수 있으므로, 전체 시스템 복원이 꼭 필요한 사용자가 아니라면 베이 수가 많은 상위 모델을 서둘러 살 이유가 줄어든다.

핵심은 간단하다. 앱과 설정까지 한 번에 되살리려면 모델·베이·디스크 배치를 원본에 맞추고, 파일이 목적이면 Hyper Backup Explorer를 포함한 선택 복원 경로를 준비한다. 구매 결정은 백업 성공 여부가 아니라 실제로 꺼내 볼 파일과 서비스까지 복원되는지 확인한 뒤 내려야 한다.
