TrueNAS SCALE 25.10.7은 2026년 9월 2일 공개된 25.10 계열 최신 유지보수 릴리스다. Linux 커널이 6.12.105로 올라갔고, 연결이 끊긴 NFSv4.1 클라이언트가 요청을 중복 처리할 때 발생하던 커널 패닉이 수정됐다. 홈서버라면 TrueNAS 26 베타로 넘어가기보다, 먼저 이 안정 계열 패치를 백업 후 적용하는 쪽이 현실적이다.

## 이번 업데이트에서 확인할 부분

공식 버전 노트에서 일반 사용자가 직접 체감할 만한 핵심은 다음 세 가지다.

| 항목 | 25.10.7에서 달라진 점 | 홈서버 판단 |
|---|---|---|
| Linux kernel | 6.12.105로 업데이트 | 보안·드라이버 측면에서 적용 가치 있음 |
| NFSv4.1 | 재연결 중 요청 중복으로 인한 패닉 수정 | Proxmox·Linux 클라이언트 사용자는 우선 적용 |
| iSCSI HA | 피어 컨트롤러 이탈 중 대상 해제 충돌 수정 | 일반 단일 NAS에는 영향이 작음 |

이 그림에서 봐야 할 것은 버전 숫자보다, 업데이트 전후에 저장소와 공유 프로토콜을 각각 확인해야 한다는 점이다.

## 업데이트 전 10분 점검

내 테스트 환경은 TrueNAS SCALE 25.10.6, ZFS 데이터 풀 1개, SMB 공유 3개, Apps 화면에서 운영하는 Jellyfin과 Uptime Kuma다. VM이나 iSCSI를 쓰지 않는다면 아래 순서만으로도 충분하다.

1. **System Settings → General → Manage Configuration**에서 설정 파일을 다운로드한다.
2. **Storage → Pools**에서 풀 상태가 `ONLINE`인지 확인한다.
3. **Data Protection → Snapshots**에서 최근 스냅샷과 복제 작업 성공 여부를 확인한다.
4. Apps의 실행 목록과 각 서비스의 데이터 경로를 메모한다.

풀 상태를 명령줄에서도 확인하고 싶다면 Shell에서 아래 명령을 실행한다. `zpool status`에 `DEGRADED`나 `UNAVAIL`이 보이면 업데이트보다 디스크 문제 해결이 먼저다.

```bash
zpool status
zfs list
```

설정 파일은 디스크 고장 복구용 백업이 아니다. 사진이나 문서 원본은 별도 NAS, 외장 디스크 또는 원격 저장소에도 1개 이상 복사해야 한다.

## TrueNAS 25.10.7 적용

웹 UI에서 **System Settings → General → Manage Configuration**으로 설정을 저장한 뒤, **System Settings → Update**를 연다. 업데이트 확인 후 25.10.7을 선택하고, 재부팅 예약 시간을 정한다. Jellyfin을 쓰는 집에서는 가족이 미디어를 보지 않는 시간으로 잡는 편이 덜 불편하다.

설치 중 전원을 끄면 안 된다. 화면이 잠시 멈춰도 10~20분은 기다리고, 재부팅 뒤에는 브라우저를 새로 열어 버전과 풀 상태를 확인한다. 25.10 안정판에서 26-BETA로 바꾸는 선택지는 이번 작업과 분리한다. 베타는 앱 호환성과 API 변경까지 함께 검증해야 한다.

## 재부팅 후 확인 목록

| 확인 순서 | 성공 기준 |
|---|---|
| 버전 | Dashboard에 TrueNAS 25.10.7 표시 |
| 저장소 | Pools가 `ONLINE`, 디스크 오류 없음 |
| SMB | 다른 PC에서 파일 생성·삭제·대용량 복사 가능 |
| NFS | Linux/Proxmox 클라이언트에서 마운트와 파일 읽기 가능 |
| 앱 | Jellyfin 재생, Uptime Kuma 모니터링 정상 |
| 백업 | 스냅샷·복제 작업이 새 시간으로 실행됨 |

NFS를 사용한다면 클라이언트에서 마운트 상태도 직접 확인한다. 서버 UI가 정상이어도 클라이언트가 이전 연결을 붙잡고 있을 수 있다.

```bash
findmnt -t nfs,nfs4
touch /mnt/media/update-check.txt
rm /mnt/media/update-check.txt
```

내가 예전에 놓쳤던 부분은 앱이 `Running`으로 보인다는 이유만으로 끝낸 것이다. 실제로는 Jellyfin 라이브러리 스캔이 멈춰 있었고, SMB 쓰기 테스트를 하고서야 발견했다.

## 적용을 미뤄야 하는 경우

풀에 오류가 있거나, 최근 스냅샷·복제가 실패했거나, 업무 중인 NFS 공유가 있으면 먼저 복구한다. 업데이트 직후 문제가 생기면 **System Settings → Boot**에서 이전 부트 환경을 확인할 수 있지만, 그것이 데이터 백업을 대신하지는 않는다.

TrueNAS 25.10.7은 새 기능을 시험하는 버전이 아니라 운영 중인 25.10을 다듬는 패치다. 25.10.x를 쓰는 홈서버라면 설정 백업, ZFS 상태 확인, 공유·앱 테스트까지 한 묶음으로 진행하면 적용 판단이 쉬워진다.
