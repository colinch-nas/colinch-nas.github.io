QNAP QTS 5.2.10.3577(build 20260731)이 공개됐다. 다만 모든 QNAP에 한 번에 적용되는 공통 업데이트는 아니다. QNAP 공식 커뮤니티의 펌웨어 게시물에 모델별 적용 대상이 나뉘어 있으므로, 버전 숫자만 보고 수동 설치하면 안 된다. 이번 업데이트는 운영 NAS를 멈출 수 있는 작업인 만큼 설정 백업과 Docker 컨테이너 확인을 묶어서 진행하는 게 안전하다.

## 이번 업데이트에서 확인할 것

| 항목 | 확인 기준 |
|---|---|
| 버전 | QTS 5.2.10.3577, build 20260731 |
| 배포 기준 | 모델별 선택 배포, 모든 QNAP에 즉시 표시되지 않음 |
| 작업 영향 | 재부팅과 서비스 중단 가능 |
| 업데이트 전 필수 | 구성 백업, 스냅샷 또는 외부 백업, 컨테이너 목록 |

그림에서 볼 부분은 펌웨어 버전 자체보다 업데이트 전에 백업과 서비스 목록을 함께 확인하는 흐름이다.

## 내 모델에 표시되는지 확인

QTS에서 **제어판 → 시스템 → 펌웨어 업데이트 → 라이브 업데이트**로 들어간다. `업데이트 확인`을 눌렀을 때 QTS 5.2.10.3577이 보이지 않으면 강제로 다른 모델의 펌웨어를 내려받지 않는다. QNAP은 모델과 하드웨어 구성에 따라 펌웨어가 다르다.

화면에 버전이 표시되기 전에는 아래 세 가지를 기록해 둔다.

- NAS 모델명과 현재 QTS 빌드
- 설치된 앱 목록과 Container Station 프로젝트 이름
- NAS가 사용하는 고정 IP, 공유폴더, 포트포워딩 목록

특히 TS-464 같은 Intel 기반 모델에서 돌아가는 컨테이너를 ARM 모델용 패키지와 섞어 생각하면 안 된다. 펌웨어 파일은 반드시 QNAP Download Center에서 모델을 직접 선택해 받아야 한다.

## 업데이트 전 백업 순서

QTS 설정 백업은 **제어판 → 시스템 → 백업/복원 → 설정 백업**에서 내려받는다. 이 파일은 사용자·공유폴더·네트워크 설정 복구에 쓰지만, Docker 볼륨 안의 데이터까지 대신 백업해 주지는 않는다.

Container Station을 쓴다면 프로젝트별로 compose 파일과 환경 변수를 NAS 바깥에 복사한다. 목적은 컨테이너를 다시 만드는 것이 아니라, 재부팅 후 어떤 포트와 경로를 복원해야 하는지 잃지 않는 데 있다.

```bash
# compose 파일과 환경 변수의 위치를 확인한 뒤 별도 백업 디스크로 복사한다
cp -a /share/Container/compose/my-stack /share/external/backup/qnap-before-5.2.10/
```

명령어 경로는 각자의 공유폴더 이름에 맞게 바꿔야 한다. SSH에서 실제 경로를 확인하지 않고 그대로 붙여 넣으면 백업했다고 착각하기 쉽다. 사진·문서처럼 원본이 하나뿐인 데이터는 HBS 3, rsync, USB 디스크 중 하나로 별도 복사하고 백업 파일을 직접 열어 확인한다.

## 업데이트 후 점검 순서

재부팅이 끝나면 **제어판 → 시스템 상태**에서 QTS 버전을 확인하고, 아래 순서로 서비스를 살핀다.

1. 공유폴더를 PC에서 읽고 쓰기
2. SMB 사용자 권한과 네트워크 드라이브 연결
3. Container Station 실행 및 프로젝트 상태
4. Jellyfin·Home Assistant·Uptime Kuma의 웹 포트 접속
5. HBS 3 백업 작업과 예약 실행 상태
6. 알림 센터의 디스크·앱 오류 로그

QTS 업데이트 직후에는 NAS가 정상 부팅돼도 Container Station 프로젝트가 자동 시작하지 않는 경우가 있다. 앱 화면에서 프로젝트가 `Running`인지 확인하고, 꺼진 컨테이너는 무조건 재시작하기보다 로그에서 마운트 경로와 권한 오류를 확인한다.

## 업데이트를 미뤄야 하는 경우

업데이트 화면에 대상 버전이 뜨더라도 백업 작업이 실행 중이거나 RAID 스크럽·디스크 검사 중이면 일정을 바꾼다. 외부에 QTS 관리 포트를 열어 둔 NAS라면 업데이트를 미루는 비용이 더 클 수 있지만, 적용 전에 포트포워딩을 닫고 로컬 네트워크에서 작업하는 편이 낫다. 관리자 계정의 2단계 인증과 자동 차단도 함께 확인한다.

QTS 5.2.10.3577은 모델별 배포 소식부터 확인해야 하는 버전이다. `대상 모델 확인 → QTS 설정 백업 → Docker·백업 데이터 별도 보관 → 업데이트 → 공유폴더와 컨테이너 검증` 순서를 지키면 재부팅 자체보다 복구에 드는 시간을 크게 줄일 수 있다.
