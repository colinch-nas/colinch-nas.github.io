이 그림에서 볼 것은 화려한 서버 장비가 아니라, 업데이트 전에 저장장치 상태와 백업 경로를 확인해야 한다는 점이다.

TrueNAS SCALE 25.10.6이 2026년 8월 12일 공개됐다. 이번 버전은 Linux 커널을 6.12.99로 올리고 250개가 넘는 upstream CVE를 반영했다. 내 홈서버처럼 SMB 공유와 Docker 앱을 함께 쓰는 환경에서는 새 기능보다 “업데이트 후 풀이 온라인이고 앱이 다시 뜨는가”를 확인하는 절차가 더 중요하다.

## 25.10.6에서 확인할 변화

| 항목 | 25.10.6 기준 | 홈서버에서 볼 부분 |
|---|---|---|
| 커널 | Linux 6.12.99 | 부팅 후 네트워크·USB 장치 |
| NVIDIA | 580.173.02 계열 | GPU 트랜스코딩 앱과 드라이버 |
| 보안 | 250개 이상 upstream CVE 수정 | 외부 공개 NAS는 적용 우선순위 높음 |
| 디스크 점검 | SMART 예약 작업을 cron으로 이전 | 기존 검사 일정이 살아 있는지 확인 |

TrueNAS 공식 문서 기준으로 기존 SMART 테스트 일정은 자동으로 이전되지만, 자동 이전을 믿고 끝내면 안 된다. `Tasks → S.M.A.R.T. Tests`에서 주간 검사 일정이 실제로 남아 있는지 확인했다. GPU를 쓰지 않는 미디어 서버라면 NVIDIA 변경은 영향이 작지만, Jellyfin에서 하드웨어 트랜스코딩을 쓴다면 별도 점검 대상이다.

## 업데이트 전 10분 점검

테스트 환경은 TrueNAS SCALE 25.10.5, 4베이 ZFS 풀, SMB 공유, Apps 화면에서 운영하는 Jellyfin과 Uptime Kuma다. 버전이 다르면 메뉴 이름이 조금 달라질 수 있다.

| 순서 | 확인 위치 | 통과 기준 |
|---|---|---|
| 1 | Storage → Pools | 풀 상태 `ONLINE` |
| 2 | Data Protection → Snapshots | 최근 스냅샷 존재 |
| 3 | System → General → Manage Config | 설정 파일 다운로드 완료 |
| 4 | Apps | 실행 중 앱과 포트 기록 |
| 5 | Network | 고정 IP·게이트웨이 기록 |

업데이트 전에 설정 파일을 다운로드하고, 중요한 공유 폴더는 다른 디스크나 외부 저장소에도 복사한다. 스냅샷은 실수로 파일을 지웠을 때 유용하지만, 같은 풀의 디스크 고장까지 해결하는 백업은 아니다. 이 구분을 놓치고 “스냅샷이 있으니 안전하다”고 생각한 적이 있는데, 풀 자체가 문제면 스냅샷도 같이 접근할 수 없었다.

## 업데이트 적용과 부팅 확인

`System Settings → General → Update`에서 25.10.6을 선택한다. 자동 재부팅을 허용하기 전에 SMB 복사, 복제, 앱 작업이 없는지 확인한다. 대용량 파일 복사 중에 재부팅하면 클라이언트가 오류를 내고, 재연결 뒤 파일 상태를 다시 확인해야 해서 시간이 더 든다.

부팅이 끝나면 화면만 보지 말고 셸에서 풀 상태를 확인한다. 아래 명령은 데이터 변경 없이 현재 ZFS 상태만 출력한다.

```bash
zpool status -x
zpool list
```

`all pools are healthy`가 나오고 풀 상태가 `ONLINE`이면 1차 통과다. `DEGRADED`, `SUSPENDED`가 보이면 앱 설정을 만지기보다 디스크와 시스템 로그부터 확인한다.

앱은 한꺼번에 열지 않고 핵심 순서대로 확인했다. SMB 공유에서 작은 파일을 열고 저장한 뒤 Jellyfin 재생, Uptime Kuma의 HTTP 감시, 예약 스냅샷 순서로 점검하면 장애 범위를 좁히기 쉽다.

## 문제가 생겼을 때 되돌리는 기준

부팅 환경이 남아 있다면 `System Settings → Boot → Boot Environment`에서 25.10.5 항목을 확인한다. 네트워크가 끊겼거나 앱 하나가 실행되지 않는 정도라면 로그를 확인한 뒤 설정을 고치는 편이 낫다. 반대로 풀이 import되지 않거나 전체 공유가 사라졌다면 반복 재부팅하지 말고 이전 부팅 환경으로 돌아갈 준비를 한다.

업데이트 결과는 아래처럼 기록해두면 다음 장애 때 비교하기 편하다.

```text
업데이트: 25.10.5 → 25.10.6
풀: ONLINE
SMB 읽기/쓰기: 정상
앱: Jellyfin, Uptime Kuma 정상
SMART 일정: 유지 확인
GPU 트랜스코딩: 미사용 또는 재생 확인
```

TrueNAS 25.10.6은 보안 수정 폭이 커서 홈서버에도 적용할 이유가 충분하다. 다만 업데이트 버튼을 누르는 것보다 설정 백업, ZFS 상태 확인, 앱별 테스트, 이전 부팅 환경 확인을 한 묶음으로 준비하는 것이 실제 운영에서는 더 안전하다.
