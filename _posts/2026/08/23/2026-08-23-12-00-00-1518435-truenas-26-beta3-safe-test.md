TrueNAS 26-BETA.3은 운영 NAS에 바로 올릴 버전이 아니다. 2026년 8월 20일 공개된 초기 릴리스로 Linux 커널과 OpenZFS가 갱신됐고, dRAID 전용 스페어와 NVIDIA 장기지원 드라이버 같은 변화가 들어갔다. 공식 버전 노트도 Early Release는 중요한 작업에 사용하지 말라고 안내한다. 새 기능이 궁금하다면 Proxmox VM이나 남는 SSD에서 네트워크와 SMB까지만 확인하는 선이 현실적이다.

그림에서 볼 부분은 운영 데이터와 테스트 장비를 분리하고, 화면에 보이는 점검 항목을 하나씩 통과시키는 구성이다.

## 내 테스트 환경

| 항목 | 기준 | 이유 |
|---|---|---|
| 대상 버전 | TrueNAS 26-BETA.3 | 2026-08-20 공개 초기 릴리스 |
| 가상화 | Proxmox VE 9.x VM | 운영 풀과 분리 |
| 디스크 | 부팅 32GB + 테스트 디스크 2개 | ZFS 미러와 SMB 확인 |
| 네트워크 | 브리지 `vmbr0`, 내부 IP 고정 | 다른 PC에서 공유 폴더 테스트 |

운영 중인 ZFS 풀을 VM에 연결하지 않는 게 핵심이다. 새 버전에서 풀을 열고 기능 플래그를 올리면 이전 버전으로 돌아갈 때 제약이 생길 수 있다. 베타 테스트에 운영 디스크를 가져오는 순간, 기능 확인이 아니라 마이그레이션 작업이 된다.

## ISO와 VM 준비

TrueNAS 공식 버전 노트에서 BETA.3 ISO와 체크섬을 받은 뒤, 파일을 검증한다. 다운로드가 끝났다고 바로 부팅하지 말고 해시부터 확인한다.

```bash
sha256sum TrueNAS-SCALE-26.0-BETA.3.iso
```

Proxmox에서는 BIOS는 기본 SeaBIOS, CPU는 2코어 이상, 메모리는 8GB 이상으로 잡았다. 테스트 목적이면 디스크 캐시를 공격적으로 설정할 필요가 없다. VM에 가상 디스크 두 개를 추가하고, 설치 대상은 부팅 디스크로만 지정한다. 데이터 디스크를 설치 화면에서 잘못 고르면 테스트 시작 전에 디스크를 지우게 된다.

## 설치 후 세 가지만 확인

관리자 계정을 만든 뒤 고정 IP를 설정한다. 공유기 DHCP 예약과 TrueNAS 내부 설정을 동시에 건드리면 주소가 바뀌는 삽질이 생기므로 한 곳만 관리하는 편이 낫다.

1. **스토리지**: 두 테스트 디스크로 미러 풀을 만들고 `ONLINE` 상태인지 확인한다.
2. **SMB**: 테스트 데이터셋을 만들고 Windows·macOS에서 파일 생성, 이름 변경, 삭제를 각각 실행한다.
3. **앱과 VM**: 앱 하나를 설치해 로그와 재시작을 확인한다. 베타에서 컨테이너·가상머신 문제가 보고될 수 있으므로 중요한 서비스는 복제하지 않는다.

SMB 권한은 공유 폴더가 열린다는 이유만으로 끝내면 안 된다. 일반 사용자로 읽기·쓰기 범위를 확인하고, 관리자 계정으로만 접근되는 폴더와 구분한다. 스냅샷도 하나 만들어 파일을 지운 뒤 복구되는지 확인하면 UI를 구경하는 것보다 얻는 정보가 많다.

## 운영 NAS에 적용할 시점

지금은 25.10 안정 계열을 유지하고, BETA.3에서는 하드웨어 호환성·네트워크·SMB·백업 스크립트만 관찰하는 게 맞다. 특히 백업 자동화가 API를 호출한다면 메이저 버전 전환 전에 호출 방식과 인증을 따로 점검해야 한다. 테스트 VM에서 정상이라고 운영 풀의 앱까지 안전하다는 뜻은 아니다.

| 확인 결과 | 판단 |
|---|---|
| ISO 검증 실패 | 다운로드를 폐기하고 다시 받는다 |
| SMB만 확인 | 운영 업그레이드 근거로 부족하다 |
| 앱·백업·복구까지 확인 | 별도 백업 후 안정 릴리스에서 재검토한다 |

짧게 정리하면 `ISO 해시 확인 → 분리된 VM 구성 → 미러·SMB 점검 → 스냅샷 복구 → 운영 장비는 유지` 순서다. TrueNAS 26의 새 기능을 빨리 보는 것보다, 되돌릴 수 있는 테스트 경계를 먼저 만드는 편이 홈서버에서는 시간을 아낀다.
