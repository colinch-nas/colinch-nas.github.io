그림에서 볼 것은 Home Assistant 자체보다 NAS의 Docker 포트와 프록시가 연결되는 지점이다.

Home Assistant 2026.8을 NAS Docker에 올릴 때는 컨테이너 포트보다 **기존 역방향 프록시가 어느 포트로 전달하는지**부터 확인해야 한다. 2026년 8월 5일 공개된 2026.8부터 새 설치의 기본 웹 포트가 80으로 바뀌었고, 기존 설치의 8123 구성이 모두 자동으로 바뀌는 것은 아니다. Nginx Proxy Manager(NPM, 외부 도메인 요청을 내부 서비스로 넘기는 중계 서버)를 쓰는 환경에서 이 차이가 특히 헷갈린다.

## 내 NAS 환경과 포트 확인

테스트 환경은 Synology DSM 7.2.2, Container Manager, Home Assistant Container 2026.8.0, NPM 2.12다. 공유기에서는 80·443을 NAS로 넘기고 Home Assistant는 외부에 직접 노출하지 않았다. `docker ps` 결과와 compose 파일, NPM Proxy Host의 전달 포트가 모두 같은지 확인한다.

## 기존 8123 구성을 유지하는 방법

이미 작동하는 NAS라면 포트를 바꾸지 않고 8123을 유지하는 편이 안전하다. 업데이트 전에 설정 폴더를 복사하고 compose 파일의 매핑을 고정한다. 아래처럼 호스트 8123을 컨테이너 8123에 연결하면 된다.

```yaml
services:
  homeassistant:
    container_name: homeassistant
    image: ghcr.io/home-assistant/home-assistant:2026.8.0
    volumes:
      - ./config:/config
      - /etc/localtime:/etc/localtime:ro
    ports:
      - "8123:8123"
    restart: unless-stopped
```

NPM Proxy Host의 `Forward Hostname/IP`에는 NAS 또는 컨테이너 이름, `Forward Port`에는 `8123`을 입력한다. 서로 다른 Docker 프로젝트라면 컨테이너 이름 대신 NAS 내부 IP를 쓰는 편이 덜 헷갈린다.

## 80 포트로 바꿀 때 생기는 문제

새 compose 예제를 따라 `80:80`으로 바꾸면 NAS의 다른 서비스와 충돌할 수 있다. 특히 NPM이 이미 호스트 80·443을 사용한다면 Home Assistant에 호스트 80을 다시 할당할 수 없다. 컨테이너 내부 포트만 80인 경우와 호스트 포트까지 80인 경우를 구분해야 한다.

```yaml
ports:
  - "8123:80" # 호스트 8123으로 접속하고 컨테이너 내부 80으로 전달
```

이렇게 바꿨다면 NPM의 전달 포트도 80으로 수정한다. 기존 컨테이너가 8123에서 듣는데 NPM만 80으로 바꾸면 502 Bad Gateway가 난다. 릴리스 노트의 포트와 호스트 포트 매핑을 같은 의미로 보면 생기는 오류다.

## 업데이트 전후 체크리스트

- `config` 폴더와 compose 파일을 별도 위치에 복사한다.
- `docker ps` 또는 Container Manager에서 실제 포트 매핑을 기록한다.
- NPM Proxy Host의 전달 포트가 compose와 같은지 확인한다.
- 브라우저 접속뿐 아니라 모바일 앱, webhook, MQTT 자동화도 테스트한다.
- `docker logs homeassistant --tail 100`에서 포트 오류를 확인한다.
- 호스트 80·443을 Home Assistant에 직접 열지 않는다.

Cloudflare Tunnel을 함께 쓴다면 서비스 주소도 확인한다. `http://homeassistant:8123`을 쓰던 구성이 컨테이너 내부 포트를 80으로 바뀐 경우에는 `http://homeassistant:80`으로 맞춘다. 외부 도메인이 열려도 webhook과 자동화가 정상이라는 뜻은 아니다.

## 짧게 정리

Home Assistant 2026.8의 포트 80 변경은 새 설치와 기존 설치를 나눠서 봐야 한다. NAS에서 NPM을 이미 운영 중이라면 `8123:8123`을 유지하고 프록시 전달 포트만 일치시키는 방식이 가장 안정적이다. 80으로 전환할 때는 호스트 포트 충돌, NPM·Cloudflare Tunnel 대상 포트, 모바일 앱과 webhook을 함께 확인해야 한다.
