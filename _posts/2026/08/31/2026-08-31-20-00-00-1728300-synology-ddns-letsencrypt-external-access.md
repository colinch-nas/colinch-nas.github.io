![Synology NAS 외부접속과 HTTPS 설정](https://images.unsplash.com/photo-1558494949-ef010cbdcc31?w=1200&q=80)
*외부접속은 포트 하나를 여는 작업이 아니라 도메인, 인증서, 방화벽을 함께 맞추는 작업이다.*

시놀로지 NAS를 집 밖에서 쓰려면 `192.168.1.20:5001` 같은 내부 주소를 그대로 노출하지 말고, DDNS(유동 IP를 도메인으로 연결하는 서비스)와 HTTPS 인증서를 함께 설정하는 편이 낫다. 내가 확인한 환경은 Synology DSM 7.2.2, 공유기 공인 IPv4, NAS 내부 IP `192.168.1.20`이다. 결과적으로 `https://nas.example.com`으로 DSM에 접속하고, 서비스별 도메인은 역방향 프록시(외부 요청을 내부 서비스로 전달하는 중계 서버)로 분리했다.

## 준비 조건

| 항목 | 예시 값 | 확인할 곳 |
|---|---|---|
| DSM | 7.2.2 | 제어판 → 정보 센터 |
| NAS 주소 | 192.168.1.20 | 제어판 → 네트워크 |
| DDNS | nas.example.synology.me | 제어판 → 외부 액세스 |
| 공유기 포트 | TCP 80, 443 | 공유기 포트포워딩 |
| 도메인 | nas.example.com | DNS 관리 화면 |

공인 IP가 아닌 CGNAT 환경이면 포트포워딩을 해도 NAS까지 도달하지 않는다. 공유기의 WAN IP와 포털에서 보이는 공인 IP가 다른지 먼저 확인한다. 통신사 인터넷에서 100.64.0.0/10 대역을 받았다면 Tailscale 같은 VPN을 쓰는 방향이 현실적이다.

## DDNS부터 등록한다

DSM에서 **제어판 → 외부 액세스 → DDNS → 추가**를 연다. 서비스 제공업체는 Synology를 선택하고 호스트 이름을 정한다. 저장 후 상태가 `정상`인지 확인한다. 여기서 실패하면 인증서 발급으로 넘어가도 계속 실패한다.

공유기에서는 포트포워딩 규칙을 다음처럼 만든다.

| 외부 포트 | 내부 IP | 내부 포트 | 용도 |
|---:|---|---:|---|
| 80 | 192.168.1.20 | 80 | Let's Encrypt 발급·갱신 |
| 443 | 192.168.1.20 | 443 | HTTPS 접속 |

DSM 관리 포트 `5000`, `5001`을 외부에 직접 열 필요는 없다. **제어판 → 로그인 포털 → DSM → HTTPS 포트**는 내부에서만 사용할 번호로 두고, 공유기에는 80과 443만 전달한다. 포트 80을 닫은 상태에서는 HTTP-01 방식의 인증서 발급이 막히는 경우가 많았다.

## Let's Encrypt 인증서 발급

**제어판 → 보안 → 인증서 → 추가 → 새 인증서 추가**를 선택한다. `Let's Encrypt에서 인증서 얻기`를 고르고 다음 값을 입력한다.

```text
도메인 이름: nas.example.com
이메일: 실제 알림을 받을 주소
주체 대체 이름: *.example.com (와일드카드는 DNS 검증을 사용할 때만)
```

일반 DDNS 주소라면 주체 대체 이름은 비워도 된다. 발급이 끝난 뒤 **인증서 → 구성**에서 `nas.example.com`을 DSM 서비스에 연결한다. 인증서가 발급됐는데도 경고가 뜬다면 브라우저 주소가 DDNS 이름과 다른지, 또는 예전 인증서가 서비스에 연결돼 있는지 확인한다.

## 서비스별 역방향 프록시

DSM 7.2에서는 **제어판 → 로그인 포털 → 고급 → 역방향 프록시**에서 규칙을 추가한다. 예를 들어 Docker의 Jellyfin이 `192.168.1.20:8096`에서 실행 중이면 아래처럼 입력한다.

```text
설명: jellyfin
소스 프로토콜: HTTPS
소스 호스트 이름: jellyfin.example.com
소스 포트: 443
대상 프로토콜: HTTP
대상 호스트 이름: 127.0.0.1
대상 포트: 8096
```

DNS에는 `jellyfin.example.com`을 NAS를 가리키는 레코드로 추가하고, 같은 인증서를 해당 도메인에도 연결한다. Docker 서비스 포트 `8096`을 공유기에 따로 열지 않는 것이 핵심이다. 외부에는 443만 보이고 내부 서비스 포트는 숨겨진다.

## 실패했던 지점과 보안 체크

처음에는 DDNS만 만들면 끝난다고 생각했지만, 인증서 자동 갱신은 90일 주기라서 발급 성공보다 갱신 경로가 중요했다. 갱신 시점에도 DNS가 현재 공인 IP를 가리키고 80 포트 검증이 통과해야 한다.

- DSM 관리자 계정에는 2단계 인증을 켠다.
- 공유기에서 5000, 5001, 8096 등 불필요한 포트포워딩을 삭제한다.
- 제어판 → 보안 → 방화벽에서 필요한 국가·포트만 허용한다.
- 인증서 만료일이 30일 이내인지 정기적으로 확인한다.
- 외부 공개가 꼭 필요하지 않은 관리 화면은 Tailscale VPN으로만 접속한다.

이 설정은 HTTPS를 추가할 뿐 백업을 대신하지 않는다. 랜섬웨어나 계정 탈취에 대비해 Hyper Backup 또는 다른 장치로 별도 백업을 유지해야 한다.

## 짧은 요점 정리

Synology 외부접속의 최소 구성은 DDNS → 80/443 포트포워딩 → Let's Encrypt 인증서 → 역방향 프록시 순서다. DSM과 Docker 서비스 포트를 직접 공개하지 않고 443 하나로 진입점을 통일하면 관리가 단순해진다. CGNAT이면 이 방법에 시간을 쓰기보다 Tailscale VPN부터 검토하는 편이 빠르다.
