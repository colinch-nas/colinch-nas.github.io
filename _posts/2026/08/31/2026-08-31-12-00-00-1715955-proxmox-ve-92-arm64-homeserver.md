Proxmox VE 9.2에 공식 ARM64 지원이 추가됐다. 2026년 8월 5일 발표됐고 다운로드 페이지에는 `9.2-1-arm64` ISO가 올라와 있다. 다만 이 소식만 보고 라즈베리파이나 아무 ARM 미니PC에 설치하면 곤란하다. 공식 발표에서 첫 검증 대상은 NVIDIA Grace·Vera 계열 서버다. 집에서 시험한다면 보드 호환성부터 확인하고, 운영 NAS와 분리된 SSD에 설치하는 순서가 맞다.

## ARM64 홈서버에 맞는지 판단하기

같은 ARM64라도 부트 펌웨어, NIC 드라이버, 저장장치가 다르다. 내가 보려는 장비가 단순히 `aarch64`라고 표시되는 것만으로는 부족하다.

| 확인 항목 | 설치 전 판단 기준 |
|---|---|
| CPU 아키텍처 | `aarch64` 또는 `arm64`인지 확인 |
| 부트 방식 | UEFI 또는 제조사가 제공한 ISO 부팅 방법 필요 |
| 메모리 | VM을 돌릴 계획이면 8GB보다 16GB가 현실적 |
| 저장장치 | 부트 디스크와 VM 디스크를 가능하면 분리 |
| 네트워크 | 브리지에 연결할 유선 NIC가 있는지 확인 |

이미 Ubuntu Server가 올라간 장비라면 이 명령어로 CPU와 가상화 플래그를 확인한다. ARM 보드에서 KVM이 빠져 있으면 Proxmox를 설치해도 VM 성능을 기대하기 어렵다.

```bash
uname -m
lscpu | grep -E 'Architecture|Virtualization|Model name'
ls -l /dev/kvm
```

`uname -m`이 `aarch64`이고 `/dev/kvm`이 존재해야 한다. `/dev/kvm`이 없다고 바로 고장으로 단정하지 말고, 펌웨어에서 가상화 옵션을 켰는지와 해당 보드가 KVM을 지원하는지 제조사 문서를 확인한다.

## ISO 검증과 설치

Proxmox 다운로드 페이지의 ARM64 파일은 2026년 8월 5일 기준 1.50GB이며 SHA-256 값도 함께 제공된다. USB에 굽기 전에 해시가 일치하는지 확인한다.

```bash
sha256sum proxmox-ve_9.2-1-arm64.iso
```

발표된 공식 해시는 다음 값이다.

```text
b1619dcd1f5b1a6d67d77b59e7e2fa2033174551d1e1b9dc22b2171ec093abbd
```

설치 화면에서는 운영 데이터가 있는 디스크를 선택하지 않는다. ARM 보드의 eMMC나 NVMe가 하나뿐이면 테스트용 SSD를 USB로 연결하는 편이 낫다. 설치 후 관리 화면은 `https://설정한-IP:8006`으로 접속한다. 처음부터 외부 포트포워딩을 열지 말고, 같은 공유기 안에서 접속이 되는지부터 확인한다.

## 홈서버용 네트워크 브리지

VM이 공유기에서 별도 IP를 받아야 한다면 `vmbr0`가 물리 NIC에 연결돼 있어야 한다. 웹 UI의 **System → Network → Create → Linux Bridge**에서 물리 인터페이스를 브리지 포트로 지정하고, 관리 IP는 브리지에만 둔다.

```text
공유기 ── 유선 NIC ── vmbr0 ── Proxmox 관리 화면
                         ├── Home Assistant VM
                         └── Ubuntu Server VM
```

여기서 물리 NIC에 관리 IP와 브리지 IP를 동시에 넣으면 접속이 끊긴다. 설정을 저장하기 전에 현재 접속 경로를 유지할 콘솔이나 모니터를 준비한다. Wi-Fi만 있는 ARM 보드라면 브리지 구성이 제한될 수 있어, 홈서버 용도에는 유선 어댑터가 있는 모델이 편하다.

## VM 하나만 올려서 검증하기

테스트 VM은 CPU 2코어, 메모리 4GB, 디스크 32GB 정도로 시작한다. Home Assistant나 가벼운 Ubuntu 서비스의 부팅과 네트워크만 확인하는 목적이면 충분하다. 디스크 컨트롤러는 기본값으로 두고, 게스트 OS가 올라온 뒤 `ip a`와 `ping`으로 주소를 확인한다.

| 용도 | 시작 자원 | 확인할 것 |
|---|---:|---|
| Ubuntu 관리용 | 2 vCPU / 2GB | SSH, 업데이트 |
| Home Assistant 테스트 | 2 vCPU / 4GB | 시간 동기화, USB 동글 |
| Jellyfin 테스트 | 4 vCPU / 8GB | 하드웨어 가속 지원 여부 |

ARM64 게스트 이미지를 써야 한다. x86_64 ISO를 올리면 설치 단계에서 멈추거나 에뮬레이션으로 동작해 속도가 크게 떨어진다. Zigbee 동글이나 GPU 패스스루도 보드별 USB·IOMMU 지원 차이가 크므로, 첫 테스트에서 같이 해결하려고 하면 원인 분리가 어려워진다.

## 베타가 아니라도 남는 주의점

ARM64 공식 지원은 “모든 ARM 보드 인증 완료”라는 뜻이 아니다. 특히 일반 소비자용 SBC는 NIC, 저장장치, UEFI가 제각각이다. 지원 모델 목록이 확인되지 않으면 Proxmox를 운영 플랫폼으로 삼기보다 Ubuntu Server에 Docker를 올리는 쪽이 시간이 덜 든다.

관리 화면은 Tailscale 같은 VPN 안에서만 열고, `8006` 포트를 인터넷에 직접 공개하지 않는다. VM을 만들기 전 Proxmox 설정 백업 위치도 NAS 외부에 하나 마련한다. 테스트 디스크를 운영 풀에 연결하거나 ZFS 풀을 새 버전 기능으로 업그레이드하는 행동은 되돌리기 어렵다.

정리하면 `aarch64 확인 → /dev/kvm 확인 → 공식 ISO 해시 검증 → 빈 디스크 설치 → vmbr0 내부망 테스트` 순서다. Proxmox VE 9.2 ARM64는 저전력 홈서버 선택지를 넓혔지만, 실제 구매 판단은 CPU 이름보다 부트·NIC·KVM 호환성을 확인한 뒤 내려야 한다.
