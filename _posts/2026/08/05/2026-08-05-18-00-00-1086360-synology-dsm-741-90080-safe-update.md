2026년 8월 5일 기준 Synology NAS의 최신 안정 업데이트는 DSM 7.4 계열의 `7.4.1-90080`이다. 이번 업데이트는 무조건 바로 누르는 작업이 아니다. 공식 릴리스 노트에 일부 구형 모델은 업데이트 대상에서 제외되고, 설치 후 이전 DSM으로 되돌릴 수 없다고 적혀 있다. Docker로 Jellyfin이나 Immich를 운영 중이라면 백업과 서비스 정지 여부까지 확인한 뒤 진행하는 편이 안전하다.

## 이번 업데이트에서 확인할 내용

Synology는 2026년 6월 DSM 7.4를 공개했고, 7월 23일 `7.4.1-90080`을 배포했다. DSM 7.4에는 DSM Agent, 협업 앱, HDD 기반 저장 공간 효율화 기능이 추가됐다. 다만 DSM Agent와 일부 AI 기능은 발표 즉시 모든 NAS에서 쓸 수 있는 기능이 아니다.

| 확인 항목 | 실제 판단 기준 |
|---|---|
| 현재 버전 | DSM 7.2.x 또는 DSM 7.4.x인지 확인 |
| 모델 지원 | 제어판 알림보다 Download Center의 모델별 패치가 우선 |
| 데이터 보호 | Hyper Backup 작업 완료와 복원 가능한 백업인지 확인 |
| 컨테이너 | Container Manager, 볼륨 마운트, 자동 시작 상태 기록 |
| 작업 시간 | 재부팅과 패키지 점검을 포함해 20~40분 확보 |

그림에서 봐야 할 부분은 NAS 자체보다 업데이트 전에 확인해야 할 백업·서비스·호환성 세 가지다.

## 설치 전 체크리스트

사용 환경은 DSM 7.4 계열, Btrfs 볼륨, Container Manager로 여러 서비스를 실행하는 4베이 NAS를 기준으로 잡았다. 모델마다 표시되는 업데이트 번호가 다를 수 있으므로 아래 순서로 확인한다.

1. `제어판 → 정보 센터`에서 NAS 모델과 현재 DSM 버전을 메모한다.
2. Synology [DSM 릴리스 노트](https://www.synology.com/en-us/releaseNote/DSM?os=DSM&version=)에서 모델이 `7.4.1-90080` 대상인지 확인한다.
3. `Hyper Backup → 백업 작업`에서 최근 실행 결과가 성공인지 확인한다. 작업이 오래 실패했다면 DSM 업데이트보다 백업 원인 해결을 우선한다.
4. Container Manager에서 실행 중인 컨테이너 목록과 포트, 볼륨 경로를 캡처한다.
5. 외부 접속을 사용한다면 DDNS, 역방향 프록시(외부 도메인 요청을 내부 서비스로 전달하는 중계 서버), 인증서 만료일을 기록한다.

특히 `DS918+`, `DS916+`, `DS718+`처럼 오래된 Plus 모델은 DSM 7.4.1 대상에서 빠질 수 있다. 화면에 업데이트 알림이 없다고 해서 오류라고 단정하지 말고 모델별 릴리스 노트를 확인해야 한다.

## DSM 7.4.1-90080 설치 방법

자동 업데이트가 보이지 않거나 staged rollout(기기별 순차 배포) 대상이 아니라면 수동 설치가 필요하다.

`제어판 → DSM 업데이트`에서 현재 버전을 확인한 뒤 `업데이트 확인`을 누른다. 패치가 표시되면 릴리스 노트의 변경 사항과 재부팅 안내를 읽고 설치한다. 표시되지 않을 때는 Synology Download Center에서 NAS 모델을 선택하고 DSM 7.4.1 패치를 내려받은 뒤 같은 화면의 `수동 DSM 업데이트`로 `.pat` 파일을 지정한다.

설치 중에는 전원 버튼을 누르거나 공유 폴더에 파일을 복사하지 않는다. 업데이트가 끝나면 NAS가 재부팅되고 패키지 상태를 다시 맞추는 시간이 추가로 걸린다.

## 재부팅 후 확인할 것

웹 관리 화면에 로그인해 `제어판 → 정보 센터`에서 `7.4.1-90080`을 확인한다. 그 뒤 아래 순서로 서비스 상태를 본다.

| 순서 | 확인 내용 |
|---|---|
| 1 | 저장소 관리자에서 볼륨·스토리지 풀 경고 확인 |
| 2 | 패키지 센터에서 Container Manager와 Hyper Backup 실행 |
| 3 | 컨테이너의 자동 시작, 포트, 볼륨 마운트 확인 |
| 4 | Jellyfin·Immich 웹 접속과 외부 HTTPS 접속 확인 |
| 5 | 작업 스케줄러와 알림 이메일 정상 여부 확인 |

여기서 자주 헷갈리는 건 DSM 업데이트가 컨테이너 이미지를 업데이트해 주지는 않는다는 점이다. 컨테이너가 내려가 있다면 DSM 문제로 단정하지 말고 Container Manager의 이벤트와 로그부터 확인한다. 반대로 관리자 계정으로 외부에서 DSM 포트를 직접 공개해 두었다면 업데이트와 별개로 포트포워딩을 닫고 Tailscale 같은 VPN을 검토하는 편이 낫다.

## 결론

`7.4.1-90080`은 최신이라는 이유만으로 모든 Synology NAS에 적용할 패치가 아니다. 모델 지원 여부를 확인하고, Hyper Backup 성공 기록과 컨테이너 설정을 남긴 뒤 설치한다. 공식 안내처럼 설치 후 다운그레이드가 불가능하므로 업무용 파일이나 사진 서버라면 하루 정도 서비스 로그를 확인한 뒤 자동 업데이트를 켜는 쪽이 안전하다.
