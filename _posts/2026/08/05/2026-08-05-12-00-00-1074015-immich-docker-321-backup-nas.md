Immich 3.x 사진 서버는 `UPLOAD_LOCATION`의 사진·동영상과 PostgreSQL 데이터베이스를 같이 백업해야 한다. 사진 폴더만 복사하면 앨범, 얼굴 인식, 공유 정보가 사라지고, 데이터베이스만 보관하면 실제 원본을 복구할 수 없다. 이번 설정은 Synology NAS의 Docker Compose 환경을 기준으로 했지만, QNAP과 Ubuntu 홈서버에서도 경로만 바꾸면 그대로 적용된다.

## 백업 대상부터 나눴다

Immich 공식 문서 기준으로 데이터베이스 백업은 메타데이터만 포함한다. 사진과 동영상은 별도로 `UPLOAD_LOCATION` 전체를 보관해야 한다. 기본 자동 DB 백업은 매일 새벽 2시에 실행되고 최근 14개를 유지하지만, 이것만으로는 NAS 고장에 대비할 수 없다.

| 대상 | 예시 경로 | 빠지면 생기는 문제 |
|---|---|---|
| PostgreSQL DB | `/volume1/docker/immich/backups` | 앨범·사용자·검색 정보 손실 |
| 원본 사진·동영상 | `/volume1/photo/immich` | 실제 미디어 복구 불가 |
| Compose 설정 | `/volume1/docker/immich/.env` | 컨테이너 재생성 어려움 |

내 환경은 DSM 7.2.2, Docker Compose, Immich 3.x, 내부 주소 `192.168.0.20`이다. 백업 디스크는 같은 NAS의 `/volume1/backup/immich`에 연결했고, 이 디스크만 믿지 않도록 월 1회 외장 디스크에도 복사한다.

## 컨테이너를 멈추고 한 번에 복사한다

사진 파일과 DB의 시점이 어긋나면 복구 뒤 일부 사진이 깨질 수 있다. 공식 문서도 가장 안전한 순서로 `immich-server` 중지 후 DB와 파일을 함께 백업하는 방식을 안내한다. Compose 파일이 있는 폴더에서 실행한다.

```bash
cd /volume1/docker/immich
docker compose stop immich-server
```

DB 백업은 컨테이너 내부의 PostgreSQL 덤프를 호스트 파일로 저장한다. 컨테이너 이름을 직접 고정하지 않고 Compose 서비스 이름을 사용했다.

```bash
mkdir -p /volume1/backup/immich/$(date +%F)
BACKUP_DIR=/volume1/backup/immich/$(date +%F)

docker compose exec -T database \
  pg_dumpall -U postgres > "$BACKUP_DIR/immich-postgres.sql"

rsync -a --delete /volume1/photo/immich/ "$BACKUP_DIR/library/"
cp .env docker-compose.yml "$BACKUP_DIR/"
docker compose start immich-server
```

`--delete`는 백업 대상에서 삭제된 파일을 백업본에서도 지우므로, 이 명령은 날짜별 폴더처럼 매번 새 디렉터리를 만드는 경우에만 사용한다. 백업이 끝난 뒤 서버를 다시 올렸는지 반드시 확인한다.

## 3-2-1 규칙으로 바깥에 한 부 더 둔다

같은 NAS의 다른 공유 폴더로 복사한 것은 3-2-1의 2개 매체로 보기 어렵다. 최소한 아래처럼 구성한다.

```text
원본: NAS /volume1/photo/immich
  ├─ 1차: NAS 백업 디스크 /volume1/backup/immich
  ├─ 2차: 주 1회 분리 보관 외장 디스크
  └─ 3차: 암호화된 원격 저장소 또는 다른 장소의 NAS
```

| 점검 항목 | 확인 기준 |
|---|---|
| DB 파일 | 날짜별 `.sql` 파일이 생성됐는가 |
| 라이브러리 | 최근 업로드 사진의 파일 크기가 0이 아닌가 |
| 원격 사본 | NAS와 다른 장소·계정에 존재하는가 |
| 복구 테스트 | 테스트 폴더에서 DB와 사진을 함께 읽는가 |

복구 테스트 없이 “백업 완료”라고 판단하면 안 된다. 공식 문서의 복구 기능은 현재 DB를 덮어쓰므로, 운영 중인 인스턴스에서 바로 시험하지 말고 별도 테스트 폴더나 VM에서 진행한다. 특히 DB 백업만 복원하고 라이브러리를 나중에 붙이는 순서는 피한다. DB가 먼저 사진을 가리키고 파일이 없는 상태가 될 수 있기 때문이다.

이번 설정의 핵심은 자동 DB 백업을 믿는 게 아니라, `database → library` 순서와 외부 사본까지 함께 관리하는 데 있다. 백업 스크립트는 DSM 작업 스케줄러에서 주 1회 실행하고, 외장 디스크가 연결되지 않은 날에는 실패 알림을 보내도록 구성하는 편이 안전하다.
