TrueNAS 25.10 계열의 현재 권장 유지보수 버전은 25.10.6이다. 내 홈서버 기준으로는 새 기능이 많은 TrueNAS 26 Beta 3보다 25.10.6을 선택하는 편이 맞다. 이번 업데이트는 Linux 커널을 6.12.99로 올리고 250개가 넘는 상위 CVE를 반영했지만, 업데이트 버튼만 누르면 끝나는 작업은 아니다. 설정 파일과 공유 서비스 상태를 같이 확인해야 한다.

## 내 환경과 버전 선택

테스트 환경은 미니PC에 설치한 TrueNAS Community Edition 25.10.5, 4개 디스크 RAIDZ1 풀, SMB 공유 3개, NFS 공유 1개다. 관리 화면의 **System Settings → General → Manage Configuration**에서 설정 파일을 내려받고, **System Settings → Update**에서 현재 버전을 확인했다.

| 선택지 | 상태 | 홈서버 판단 |
|---|---|---|
| TrueNAS 25.10.6 | Maintenance, 2026-08-12 | 일반 사용·미션 크리티컬 권장 |
| TrueNAS 26 Beta 3 | Early Release, 2026-08-20 | 별도 테스트 장비에서만 |
| 25.10.5 유지 | 이전 유지보수 버전 | 특별한 호환성 문제가 있을 때만 |

공식 Software Status도 일반 사용자와 미션 크리티컬 사용자에게 25.10.6을 권장한다. 베타 버전은 새 기능 확인용이지, 사진·백업 데이터가 있는 메인 NAS를 바로 옮길 대상은 아니다.

## 업데이트 전 10분 점검

업데이트 직전에 설정 백업만 저장하면 충분하다고 생각했는데, 실제로는 진행 중인 작업이 더 위험했다. SMB로 대용량 파일을 복사하는 동안 재부팅하면 클라이언트에서 파일 오류가 보일 수 있다.

- SMB·NFS 클라이언트의 복사와 백업 작업을 중지한다.
- **Tasks → Cloud Sync Tasks**와 복제 작업이 실행 중인지 확인한다.
- **Storage → Pools**에서 풀 상태가 `ONLINE`인지 확인한다.
- **Reporting**에서 메모리 사용량과 디스크 온도를 기록한다.
- 설정 파일을 내려받고, 중요한 데이터는 외장 디스크나 다른 NAS에도 한 부 보관한다.

설정 백업은 디스크 데이터의 백업이 아니다. 부팅 장치가 고장 났을 때 설정을 복원하는 파일일 뿐이라서, 이 파일만 믿고 업데이트하면 안 된다.

## 25.10.6 적용 순서

자동 업데이트가 표시되면 **System Settings → Update → Download Updates → Apply Pending Updates** 순서로 진행한다. 자동 업데이트가 보이지 않으면 공식 다운로드 페이지에서 `.update` 파일을 받아 같은 화면의 수동 업데이트로 적용한다.

업데이트 중에는 전원을 끄지 않는다. 미니PC의 자동 절전이나 UPS 전원 제어가 재부팅을 방해하지 않는지도 확인했다. 업데이트가 끝나면 콘솔 또는 웹 UI에서 버전이 `25.10.6`인지 확인하고, 관리자 화면이 열릴 때까지 5분 정도 기다린다.

## 재부팅 후 확인할 항목

버전 숫자만 확인하고 끝냈다가 공유가 늦게 올라온 적이 있다. 아래 순서로 서비스와 디스크를 실제로 읽어보는 편이 안전하다.

| 확인 대상 | 확인 방법 | 정상 기준 |
|---|---|---|
| 풀·디스크 | Storage → Pools, Disks | 풀 `ONLINE`, 새 경고 없음 |
| SMB | 윈도우·macOS 클라이언트에서 파일 열기 | 읽기·쓰기 모두 성공 |
| NFS | 연결된 리눅스 클라이언트에서 마운트 확인 | 마운트 유지, 파일 생성 성공 |
| SMART | Tasks → S.M.A.R.T. Tests | 예약 테스트가 사라지지 않음 |
| 알림 | System Settings → Alert Settings | 부팅·디스크 오류 알림 없음 |

특히 SMART 정보가 이전과 다르게 보이면 바로 디스크 교체로 판단하지 않는다. 이번 계열에서 SMART 파싱 오류가 수정됐기 때문에, 기존 기록과 현재 `smartctl` 결과를 비교한 뒤 짧은 수동 테스트를 돌리는 게 낫다.

## 베타로 갈아타지 않은 이유

TrueNAS 26 Beta 3는 테스트할 가치는 있지만, 공유 폴더와 백업이 걸린 메인 서버에서는 업데이트 채널을 `General`로 유지했다. 베타를 쓰고 싶다면 빈 디스크나 별도 가상머신에서 설정 복원, SMB, NFS, 앱 동작을 재현한 뒤 판단한다. 풀 업그레이드는 되돌리기 어려울 수 있으므로 운영 데이터가 있는 장비에서 테스트하면 안 된다.

핵심은 세 가지다. 25.10.6으로 올리기 전 설정과 데이터 백업을 분리하고, 작업 중인 복사를 멈추며, 재부팅 후 공유·풀·SMART를 실제로 읽어본다. 이 순서를 지키면 보안 패치를 적용하면서도 “업데이트 뒤 NAS가 켜졌는데 파일이 안 보이는” 상황을 빠르게 구분할 수 있다.
