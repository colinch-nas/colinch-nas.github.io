Home Assistant 2026.8에서 새로 설치한 Home Assistant OS는 기본 웹 주소에 `:8123`을 붙이지 않아도 접속하는 방식으로 바뀌었다. 다만 이 변화는 기존 설치에는 적용되지 않는다. Synology VMM에 새 가상머신을 만들 때는 포트가 바뀐 것보다 브리지 네트워크와 IP 예약을 제대로 잡는 일이 더 중요하다.

## 확인한 환경

| 항목 | 기준 |
|---|---|
| NAS | Synology DS923+ |
| NAS 운영체제 | DSM 7.2.x, Virtual Machine Manager 2.x |
| 게스트 OS | Home Assistant OS 2026.8 |
| 네트워크 | 공유기 DHCP, 유선 LAN |
| 접속 방식 | 외부 포트포워딩 없이 내부망 접속 |

Home Assistant 공식 릴리스 노트에 따르면 `:8123` 없는 주소는 **새 Home Assistant OS 설치**부터 적용된다. 이미 운영 중인 인스턴스는 주소와 포트가 그대로라서 업데이트 후 접속 주소를 바꿀 필요가 없다. 이 부분을 모르고 기존 VM의 포트 설정을 지우면 접속이 안 되는 것처럼 보일 수 있다.

## VMM에서 네트워크를 브리지로 선택

Home Assistant OS 디스크 이미지를 준비한 뒤 VMM에서 가상머신을 생성한다. CPU 2코어, 메모리 4GB, 디스크 32GB 정도면 기본 자동화와 Zigbee 장치 관리에 충분했다. 카메라 녹화나 대형 애드온을 같이 쓸 계획이면 메모리를 6~8GB로 잡는다.

네트워크 설정에서는 NAT가 아닌 **브리지**를 선택한다. 브리지는 VM이 공유기에서 별도 IP를 받는 방식이다. NAT로 만들면 Home Assistant의 자동 발견(MDNS·멀티캐스트)이 제한되고, Zigbee 게이트웨이나 미디어 기기를 찾을 때 불필요한 예외 설정이 생긴다.

VM 전원을 켠 뒤 공유기 관리자 화면의 DHCP 임대 목록에서 `homeassistant` 또는 새로 나타난 MAC 주소를 찾는다. 이 IP로 접속한다.

```text
http://가상머신_IP
```

기존 설치처럼 무조건 `http://가상머신_IP:8123`부터 입력하지 않는 것이 포인트다. 화면이 열리지 않으면 2~5분 기다린 뒤 IP가 바뀌지 않았는지 확인한다. 첫 부팅에서는 디스크 초기화와 Supervisor 준비가 함께 진행된다.

## DHCP 예약으로 IP 고정

Home Assistant OS 안에서 수동 고정 IP를 설정할 수도 있지만, 나는 공유기의 DHCP 예약을 사용한다. VM을 재생성하거나 네트워크 어댑터를 수정할 때 게스트 OS 설정을 다시 만질 일이 줄어들기 때문이다.

공유기에서 다음처럼 예약한다.

| 설정 | 예시 |
|---|---|
| MAC 주소 | VMM 가상 NIC의 MAC |
| 예약 IP | `192.168.1.50` |
| 게이트웨이 | `192.168.1.1` |
| DNS | 공유기 주소 또는 `1.1.1.1` |

예약을 저장한 뒤 VM을 재부팅하고 같은 IP로 다시 접속한다. 이 단계가 빠지면 나중에 NAS 재부팅 후 자동화 앱의 연결 주소가 달라질 수 있다.

## 외부 접속은 8123을 열지 않는다

새 주소가 편해졌어도 인터넷에 Home Assistant를 직접 공개하는 것은 별개 문제다. 공유기에서 8123 포트를 NAS나 VM으로 포워딩하지 않는다. 집 밖에서 관리할 때는 Tailscale VPN으로 휴대폰과 NAS 네트워크를 연결하거나, 이미 운영 중인 역방향 프록시에 HTTPS를 붙인다.

관리자 계정에는 2단계 인증을 켜고, VMM 스냅샷만 믿지 말고 Home Assistant 백업을 NAS의 다른 공유 폴더에도 복사한다. VM 디스크가 손상되면 스냅샷과 원본이 함께 영향을 받을 수 있기 때문이다.

## 설정 후 확인할 것

- 내부망에서 `http://가상머신_IP` 접속
- 공유기 DHCP 예약 후 재부팅해도 같은 IP인지 확인
- 자동화 하나를 수동 실행해 트리거와 액션 점검
- Zigbee 장치 상태와 코디네이터 연결 확인
- 외부에서 8123 포트가 열려 있지 않은지 확인

Home Assistant 2026.8의 포트 변경은 새 설치의 진입 장벽을 낮춘 변화지만, 기존 VM까지 자동으로 바꾸는 업데이트는 아니다. Synology VMM에서는 브리지 네트워크, DHCP 예약, 외부 포트 미공개 세 가지를 먼저 고정하면 이후 자동화와 Zigbee 장치를 붙일 때 시행착오가 크게 줄어든다.
