그림에서 봐야 할 부분은 NAS 본체보다 백업 저장소와 복원 대상 장비를 따로 준비하는 구조다.

Synology NAS를 바꿀 예정이라면 디스크를 그대로 옮기는 방법보다 Hyper Backup 복원이 안전한 경우가 많다. 특히 원본과 대상의 모델이 다르거나, 파일시스템·RAID 구성을 새로 선택하려는 경우엔 새 볼륨을 만든 뒤 복원하는 편이 낫다. 다만 Hyper Backup의 전체 시스템 백업은 아무 NAS에나 복원되지 않는다. Synology 공식 문서 기준으로 같은 모델 또는 후속 모델만 대상이 될 수 있고, 대상 DSM은 원본과 같거나 더 최신이어야 한다.

## 구매 전에 확인할 호환성

| 확인 항목 | 통과 기준 | 실패하면 생기는 일 |
|---|---|---|
| 전체 시스템 백업 | 같은 모델 또는 후속 모델 | 패키지·설정 일괄 복원 불가 |
| DSM 버전 | 대상이 원본과 같거나 최신 | 패키지 복원이 거부될 수 있음 |
| 패키지 | 대상 모델을 지원해야 함 | 수동 재설치·재설정 필요 |
| 저장공간 | 복원 데이터와 버전을 담을 여유 | 일부 폴더만 복원하거나 작업 중단 |
| 암호화 백업 | 비밀번호·암호화 키 보관 | 백업 파일이 있어도 복원 불가 |

전체 시스템 백업을 쓰지 않고 `데이터 백업 작업`을 만들면 선택지가 넓어진다. 공유 폴더와 일부 패키지는 새 NAS로 옮길 수 있지만, 모델 전용 패키지나 라이선스는 자동 복원을 기대하면 안 된다. Synology의 마이그레이션 안내도 Hyper Backup 복원 후 패키지 상태와 라이선스를 다시 확인하라고 안내한다.

## 디스크 이동과 Hyper Backup 비교

가상 사례로 4TB 사용 데이터, 2베이 NAS에서 4베이 NAS로 교체한다고 가정한다. 디스크 이동은 새 HDD를 살 필요가 없어 초기 비용이 낮지만, 대상 모델이 파일시스템과 DSM 버전을 지원해야 한다. 반대로 Hyper Backup은 임시 백업 HDD 또는 두 NAS를 동시에 연결할 공간이 필요하다.

| 방식 | 추가 구매 | 복원 유연성 | 장애 시 비용 |
|---|---:|---|---|
| HDD 직접 이동 | 0원에 가까움 | 낮음 | 원본 디스크 문제를 함께 가져감 |
| 새 볼륨+Hyper Backup | 백업 HDD 1~2개 | 높음 | 백업이 검증됐으면 예측 가능 |
| 전체 시스템 백업 | 백업 저장소 필요 | 같은 모델·후속 모델 중심 | 패키지 조건 확인 필요 |

비용 계산은 백업용 8TB HDD 2개를 개당 18만 원, 복원 작업과 검증에 필요한 시간을 4시간으로 잡는 식으로 해야 한다. 이 가정이면 장비 추가비는 약 36만 원이다. 실제 가격과 전력비는 구매일과 사용 시간에 따라 달라지므로, HDD 가격만 보고 직접 이동을 고르면 안 된다. 4베이로 확장하면서 새 디스크를 살 계획이라면 기존 디스크는 즉시 재사용하지 말고, 최소 한 세트는 검증된 백업으로 남기는 편이 안전하다.

- [ ] 관리자 계정, 공유 폴더, Docker 경로 목록 저장

- [ ] 사진 10개, 문서 10개, 데이터베이스 덤프 1개를 시험 복원
- [ ] 복원 후 패키지 실행, 권한, 외부 접속을 각각 확인

복원 성공 알림만 확인하면 안 된다. 파일이 보이는지뿐 아니라 Docker 볼륨 권한, UID/GID, 작업 스케줄, 공유 링크 만료 상태까지 확인해야 한다. 외부 공개 중인 NAS라면 복원 검증이 끝날 때까지 포트포워딩을 열지 않는 편이 좋다.

짧게 판단하면, 같은 모델 또는 후속 모델이고 설정까지 빠르게 되살려야 하면 전체 시스템 백업을 검토한다. 모델을 바꾸거나 저장 풀을 다시 설계한다면 데이터 백업 작업으로 복원하는 편이 낫다. 백업 HDD를 사지 않아도 되는 경우는 원본 디스크를 유지한 채 별도 NAS에 이미 검증된 복사본이 있을 때뿐이다.
